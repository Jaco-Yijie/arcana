# Arcana — Product Spec 产品规格（Agent 1 / Product Lead 输出）

> 上游唯一事实来源：`docs/00-brief.md`。本文件只做**产品定义**，不含视觉设计与实现方案。
> 与简报冲突时以简报为准；本文件在简报未覆盖处做出**明确裁决**，后续 Agent 不得二次解释。

---

## 1. 产品核心价值 Core Value

1. Arcana 让用户在线上**亲手完成整个抽牌过程**——洗牌、切牌、摊牌、选牌、摆牌、翻牌每一步都由用户的真实操作产生，而不是由系统代劳后播放一段动画。
2. 牌的身份在用户进入 Session（会话）的那一刻就已经被隐藏地确定，用户的操作只是**发现**它，而不是**触发**它被生成——这是"我自己抽出来的牌"这一感受的技术前提。
3. AI 不参与"抽到哪张牌"的任何环节，AI 只在牌全部翻开之后，作为**理性分析型解读助手**出现。
4. 塔罗在本产品中的定位是**整理问题、提供新的观察角度**，不做命运预测，不替用户做决定。
5. **否决规则（用于砍功能）**：任何功能，如果它减少了用户在核心六步中的操作权/选择权/摆牌权/翻牌权，或让系统"更聪明地替用户完成一步"，一律否决——即使它更好看、更快、更省开发量。

**冲突解决优先级**：核心产品价值 > 用户体验 > 技术便利 > 视觉效果。

## 2. MVP Scope 边界

### 2.1 In Scope 范围内

| 模块 | 内容 |
|---|---|
| 首页 | 极简双入口 + 弱化次级入口 + 未完成 Session（会话）提示 |
| 牌组 Deck | **1 套**「梦幻超现实塔罗牌组」，78 张体系，6–10 张 Mock Card（模拟卡牌）+ 统一 Placeholder（占位图），统一牌背 |
| 问题输入 | 自由输入 + Mock AI 问题优化（可接受 / 可保留原问题，不强制） |
| 牌阵 Spread | **5 个**（见简报 §7），Mock 推荐 2–3 个 + 查看全部 |
| 抽牌前准备 | 直接开始 / 专注一下（轻量） |
| Tarot Table（塔罗桌） | Shuffle 洗牌 → Cut 切牌 → Fan Spread 摊牌 → Select 选牌 → Drag to Position 摆牌 → Reveal 翻牌 |
| 换牌 | 未翻开可拿回更换，翻开后锁定 |
| 牌义 | 两层展示：关键词层 → 详细牌义层 |
| AI Reading 解读 | 全部翻完后**手动触发**，先短后长，理性分析型，Mock 内容 |
| Follow-up 追问 | Mock 回答，Context（上下文）严格限定在本次 Session |
| Journal 塔罗日记 | 自动保存 localStorage，列表 + 详情 + 用户补充（心情/笔记/后来发生了什么） |
| Session Restore 会话恢复 | 抽牌过程持续保存，可继续或重新开始 |
| Share 分享 | 仅 Preview（预览），默认隐藏隐私字段 |
| Settings 设置 | 新手引导 / 音效 / 震动 / 摊牌模式 |
| 安全边界 | 高风险话题提示文案 |
| 新手引导 | 第一次明显，第二次以后自动弱化 |
| 平台 | Mobile First（移动优先），桌面可用即可 |

### 2.2 Out of Scope 范围外

**A. 简报 §26 明确不做（提出即拒绝）**：
付费、订阅、商城、社区、排行榜、好友、Google Login、云同步、Push Notification（推送通知）、完整后台、多语言、多套完整牌组、几十种牌阵、长期 AI 用户画像、AI 自动读取过去占卜、塔罗师 Marketplace（市场）、NFT、Live Streaming（直播）。

**B. 简报中已限定为"不实现/暂不做"的**：
- Free Table Mode（自由桌面模式）完整物理桌面 —— 只保留入口与说明
- 真实 3D 物理引擎洗牌
- 背景音乐
- 真实 AI API、云数据库、真实账号系统
- 桌面端专属布局

**C. 我预判会出现的 Scope Creep（范围蔓延），提前拒绝**：

| 蔓延项 | 为什么拒绝 |
|---|---|
| 「一键洗牌」「跳过洗牌」「快速抽牌」按钮 | 直接摧毁核心价值，等于系统替用户抽牌 |
| 「自动摆牌 / 牌自动飞到牌位」 | 简报 §9 明令禁止 |
| 「智能推荐最适合你的牌阵」（非 Mock 的真推荐） | 侵蚀用户选择权，且属于 AI 越界 |
| 「AI 帮你重新抽一次 / 换一张更好的牌」 | 破坏结果不可逆性，塔罗意义归零 |
| 「翻牌爆金光 / 稀有度 / SSR 特效」 | 简报 §9、§20 明令禁止，会变成游戏抽卡 UI |
| 正逆位开关、"我不想要逆位" | 属于牌组规则扩展，MVP 不做配置化 |
| 每日签到 / 连续抽牌天数 / 成就 | Gamification（游戏化），非核心，且诱导使用 |
| 日记搜索、标签、筛选、统计图表 | 日记 MVP 只需列表 + 详情，其余进 Backlog |
| 多问题多 Session 并行 | MVP 只支持**同时一个**未完成 Session |
| 分享生成精美长图 / 海报导出 | 只做 Preview，不做图片渲染管线 |
| Onboarding（新手引导）做成多页教程 | 引导必须内嵌在流程中，不做独立教学页 |
| 用户自定义牌阵 | 5 个固定牌阵就是全部 |
| 音效包 / 主题切换 / 深浅色模式 | 整站单一设计系统，不做主题化 |

## 3. 功能清单与优先级

> **P0**：不做则产品不成立，交付必须有。**P1**：完整体验所需，交付应有。**P2**：加分项，时间不足可砍。
> 「服务于自主抽牌」一列若无法回答，该功能自动降级或砍掉。

| # | 功能 | 优先级 | 所属阶段（简报 §27） | 为什么服务于「自主抽牌」 |
|---|---|---|---|---|
| F01 | Hidden Deck State 隐藏牌组状态（78 张顺序 + 隐藏正逆位）于 Session 开始时生成 | P0 | 4 | 保证牌"早已存在"，用户是在发现而非触发 |
| F02 | `systemRandom + userInteractionEntropy` 随机机制 | P0 | 5–8 | 用户操作真实参与牌序生成，抽牌结果与我的手有关 |
| F03 | Shuffle 洗牌：拖动/滑动/多次，牌堆错位重组 + 视觉反馈 | P0 | 5 | 洗牌是用户第一次实质介入牌序 |
| F04 | Cut 切牌：用户指定切点，牌堆分两部分再重组 | P0 | 6 | 切点由用户决定，系统不得自动切 |
| F05 | Fan Spread 摊牌：横向/扇形展开，全背面，可滑动浏览 | P0 | 7 | 提供"整副牌都在我面前"的可选择空间 |
| F06 | Card Selection 选牌：从牌背中主动点选任意位置 | P0 | 8 | 选择权的核心动作 |
| F07 | Drag to Position 摆牌：用户拖到 Drop Zone（放置区），带克制吸附反馈 | P0 | 9 | 摆牌权；禁止自动飞入 |
| F08 | Reveal 翻牌：用户主动 Tap/上滑触发，有重量感 | P0 | 10 | 最终翻牌权，仪式感的落点 |
| F09 | 换牌规则：未翻开可拿回更换，翻开后锁定 | P0 | 9–10 | 保护用户后悔权，同时保证结果不可逆 |
| F10 | 牌背统一，翻开前不泄露牌面 | P0 | 4 | 泄露=抽牌失去意义 |

| F12 | 问题输入页 | P0 | 11 | 用户自己定义"我在问什么" |
| F13 | 牌阵选择（Mock 推荐 2–3 + 查看全部） | P0 | 11 | 推荐只是建议，决定权在用户 |

| F15 | AI Reading 手动触发 + 先短后长 + 理性分析型 | P0 | 12 | 先看完自己的牌阵，再听解读；AI 不抢先发言 |
| F16 | Journal 塔罗日记自动保存 + 列表 + 详情 | P0 | 13 | 交付标准 §28 明确要求 |
| F17 | Session Restore 未完成会话恢复 | P0 | 14 | 抽牌被中断不等于抽牌作废，保护过程所有权 |
| F18 | 首页极简双入口 | P0 | 11 | 两条主路径的唯一起点，避免 Dashboard 稀释仪式感 |

## 4. User Journey 用户旅程

> 每一步标注 **决定权 Decision Authority**：`用户` / `系统` / `系统建议·用户决定`。
> **红线：核心六步（洗/切/摊/选/摆/翻）的决定权必须 100% 属于用户。**

### 4.1 路径 A：带着问题来

| # | 步骤 | 用户动作 | 系统行为 | 决定权 |
|---|---|---|---|---|
| A1 | 首页 | 点「带着问题来」 | 若存在未完成 Session，先提示继续/重新开始 | **用户**（继续 or 重开） |
| A2 | 牌组 | 默认已选中唯一牌组，可跳过 | 展示牌组风格与牌背 | 系统（唯一选项） |
| A3 | 输入问题 | 自由输入文字 | 不限制、不改写 | **用户** |
| A4 | 问题优化 | 选「使用优化后的问题」或「保留我的问题」 | Mock 给出 1 个优化版本 | **系统建议·用户决定** |
| A5 | 高风险检测 | 阅读提示，可继续 | 命中医疗/财务/法律/危险行为时展示安全文案 | 系统提示，**用户决定是否继续** |
| A6 | 选牌阵 | 从推荐中选，或点「查看全部牌阵」后选 | Mock 推荐 2–3 个 | **系统建议·用户决定** |
| A7 | 抽牌前准备 | 选「直接开始」或「专注一下」 | 专注模式：背景变暗 + 显示问题 + 一句提示，无强制倒计时 | **用户** |
| A8 | **Session 初始化** | 无感知 | 生成 Hidden Deck State（78 张顺序 + 隐藏正逆位），记录 `shuffleSeed` | 系统（**必须在此刻完成**） |
| A9 | **洗牌** | 拖动/滑动牌堆，可重复任意次 | 每次操作扰动牌序，累计 `interactionEntropy`，给出错位重组的视觉反馈 | **用户**（洗几次、怎么洗、何时结束） |
| A10 | **切牌** | 在牌堆上指定切点 | 牌堆按用户切点分两部分并重组 | **用户**（切点位置） |
| A11 | **摊牌** | 左右滑动浏览整副牌背 | 扇形/横向展开，全部背面朝上 | **用户**（看哪里、看多久） |
| A12 | **选牌** | 点选任意位置的牌背 | 按 index → card 从隐藏牌组取出，不现场随机 | **用户**（选哪个位置） |
| A13 | **摆牌** | 把牌拖到目标牌位 | 靠近 Drop Zone 时轻微发光/吸附，**不自动飞入** | **用户**（放哪个牌位、什么顺序） |
| A14 | 换牌 | 未翻开时可拖回并改选 | 状态自然表达，不弹 Confirm Dialog（确认弹窗） | **用户** |
| A15 | 重复 A12–A14 | 直到牌阵所需张数全部摆满 | 进度可见 | **用户** |
| A16 | **翻牌** | 逐张 Tap 或轻微上滑翻开 | 流畅、有重量感、极轻微 Glow；无爆炸粒子 | **用户**（翻哪张、翻的顺序、何时翻） |
| A17 | 牌义第一层 | 阅读牌名 + 正/逆位 + 3–5 关键词 | 不铺满整屏文字 | 系统展示 |
| A18 | 牌义第二层 | 点「查看详细牌义」 | 展开基础牌义/牌位含义/感情/事业/学业/财务/建议/象征 | **用户**（是否展开） |
| A19 | 完整牌阵 | 浏览全部已翻开的牌 | **不自动弹出 AI 解读** | **用户** |
| A20 | AI Reading | 点「开始完整解读」 | 进入 Reading Page，顶部 1–2 段核心结论 + 可展开详解 | **用户**（是否要解读） |
| A21 | 追问 | 输入追问 | Mock 回答，Context 限定为本次问题/牌阵/卡牌/正逆位/当前 Reading | **用户** |
| A22 | 自动存日记 | 无需操作 | 完整占卜自动写入 localStorage | 系统 |
| A23 | 日记补充 | 填心情 / 笔记 / 后来发生了什么 | 随时可编辑 | **用户** |
| A24 | 分享 | 选是否显示原问题 → 生成 Preview | 默认隐藏原问题/笔记/心情/后续记录 | **用户** |

### 4.2 路径 B：随缘抽一张

| # | 步骤 | 用户动作 | 系统行为 | 决定权 |
|---|---|---|---|---|
| B1 | 首页 | 点「随缘抽一张」 | — | **用户** |
| B2 | 分支选择 | 选「直接随缘」或选一个轻主题 | 轻主题四选一：今日提醒 / 最近状态 / 我需要注意什么 / 给我一个建议 | **用户** |
| B3 | 牌阵 | 无需选择 | 固定「单张牌」牌阵，牌位=指引 | 系统（路径定义） |
| B4 | Session 初始化 | 无感知 | 同 A8 | 系统 |
| B5 | 洗牌 | 同 A9 | 同 A9 | **用户** |
| B6 | 切牌 | 同 A10 | 同 A10 | **用户** |
| B7 | 摊牌 + 选牌 | 浏览后选 1 张 | 同 A11–A12 | **用户** |
| B8 | 摆牌 | 拖到唯一牌位 | 同 A13，仍需用户拖动 | **用户** |
| B9 | 翻牌 | 主动翻开 | 同 A16 | **用户** |
| B10 | 牌义 + 解读 | 同 A17–A21 | Reading 为单张版本 | **用户** |
| B11 | 存日记 | 同 A22–A23 | `question` 记为空或轻主题文案 | 系统 + **用户补充** |

## 5. Acceptance Criteria 验收标准

> 全部以 Given / When / Then 表述，QA 可客观验证。编号供 QA Agent 直接引用。

### AC-01 随机机制不得在点击后现场抽牌
- **Given** 用户已进入 Tarot Session 且 Hidden Deck State 已生成
- **When** 用户点击摊开牌堆中第 N 个位置的牌背
- **Then** 系统返回的卡牌与正逆位必须等于 Session 初始化时该 index 上已存在的值；在点击事件的调用链中不得出现任何随机数生成调用
- **验证方式**：Session 初始化后 dump（导出）隐藏牌组数组；抽完后逐张比对 `index → card + orientation` 完全一致。对同一 Session 状态重复点击同一 index，结果必须相同。

### AC-02 洗牌必须由用户操作
- **Given** 用户处于 `/table/shuffle`
- **When** 用户未进行任何拖动或滑动
- **Then** 牌序不得发生变化，且不得存在任何可跳过洗牌直接进入下一步的入口
- **And When** 用户完成 ≥1 次拖动/滑动
- **Then** 牌序必须发生可验证的变化（洗牌前后数组不相等），且 `interactionEntropy` 被写入，界面出现明显的错位重组视觉反馈
- **And** 用户可连续洗多次，每次都追加扰动；进入下一步由用户主动确认

### AC-03 切牌位置由用户决定
- **Given** 用户处于 `/table/cut`
- **When** 用户在牌堆位置 P 指定切点
- **Then** 牌堆必须按 P 分成两部分并可见地重组，重组后的牌序与 P 相关（不同的 P 必须产生不同的牌序）
- **And** 不存在任何"自动切牌""随机切牌""帮我切"的入口或默认行为
- **验证方式**：同一 Session 状态下分别选 P=20 与 P=50，得到的牌序数组必须不同。

### AC-04 摆牌必须用户拖动
- **Given** 用户已选中一张牌且该牌阵有 ≥1 个空牌位
- **When** 用户未执行拖动手势
- **Then** 牌不得移动到任何牌位
- **And When** 用户拖动该牌至 Drop Zone 有效范围并释放
- **Then** 牌落入该牌位；靠近时的吸附/发光反馈仅在拖动过程中出现，且不得在用户释放前自行完成移动
- **验证方式**：仅用点击（无 pointermove）操作，牌永远无法进入牌位。

### AC-05 翻牌必须用户触发
- **Given** 牌阵中存在已摆放但未翻开的牌
- **When** 用户不进行任何 Tap 或上滑
- **Then** 该牌保持背面朝上，不存在任何倒计时后自动翻开、或摆满后批量自动翻开的行为
- **And** 不存在「全部翻开」的一键按钮
- **And When** 用户触发翻牌
- **Then** 该牌翻面展示，动画不含爆炸粒子、强闪光、SSR 抽卡式表现

### AC-06 未翻开可换牌，翻开后不可换
- **Given** 一张牌已摆入牌位且 `revealed = false`
- **When** 用户将其拖离牌位
- **Then** 该牌位恢复为空，该牌可重新选择或换成摊开牌堆中的另一张，全程不弹 Confirm Dialog
- **And Given** 该牌 `revealed = true`
- **When** 用户尝试拖动或替换该牌
- **Then** 操作无效，牌位锁定，界面通过状态（而非弹窗警告）表达不可更改

### AC-07 抽牌前不得泄露牌面
- **Given** 任意一张尚未翻开的牌
- **When** QA 检查渲染结果、DOM、以及网络/存储可见内容
- **Then** 未翻开的牌在界面上只呈现统一牌背；不得通过视觉、动画残影、或明文属性提前暴露牌名与正逆位
- **And** 摊牌时全部 78 张（或等效数量的牌背实例）均为背面朝上

### AC-08 Session 可恢复
- **Given** 用户完成了问题、牌阵、洗牌，并已摆放部分牌但未完成流程
- **When** 用户关闭页面或刷新浏览器后重新打开首页
- **Then** 首页出现「你有一次未完成的抽牌」提示，含「继续」与「重新开始」两个选项
- **And When** 用户点「继续」
- **Then** 恢复至中断时的步骤，且问题、牌阵、Hidden Deck State（含牌序与正逆位）、已抽/已摆/已翻状态与中断前完全一致
- **And When** 用户点「重新开始」
- **Then** 旧 Session 被废弃，新 Session 重新生成全新的 Hidden Deck State

### AC-09 日记自动保存
- **Given** 用户完成了一次完整占卜（全部牌翻开且已生成 Reading）
- **When** 用户不做任何保存操作，直接退出并进入 `/journal`
- **Then** 列表中出现该次记录，含日期、问题、牌阵、卡牌缩略图、核心结论
- **And When** 用户进入详情页
- **Then** 可见原问题、优化问题、牌阵、卡牌、正逆位、详细牌义、AI Reading、后续追问
- **And When** 用户填写心情/笔记/后来发生了什么并离开页面
- **Then** 内容持久化于 localStorage，重新打开仍在

### AC-10 AI 不抢先发言
- **Given** 用户已翻开牌阵中最后一张牌
- **When** 翻牌动画结束
- **Then** 不得自动跳转或弹出 AI Reading；页面停留在完整牌阵，仅展示「开始完整解读」按钮
- **And** Reading Page 顶部为 1–2 段核心结论，其余内容默认折叠

### AC-11 AI 语气为理性分析型
- **Given** 任意 Mock Reading 或 Follow-up 文案
- **When** QA 全文检索
- **Then** 不得出现「你一定会」「命运已经决定」「你必须」等确定性/宿命论表述
- **And** 高风险话题（医疗/财务/法律/危险行为）下不得给出确定性预测

### AC-12 Follow-up Context 受限
- **Given** 用户在 Reading Page 追问
- **When** 追问内容与本次抽牌无关（如"帮我写一段代码"）
- **Then** 系统以 Mock 方式回到本次抽牌语境，不得表现为通用 Chatbot
- **And** 传入的 Context 字段仅限：当前问题、牌阵、卡牌、正逆位、当前 Reading

### AC-13 新手引导第二次弱化
- **Given** 用户第一次进入抽牌流程
- **When** 到达洗牌/切牌/选牌/摆牌/翻牌各步骤
- **Then** 显示简报 §19 对应文案
- **And Given** 用户第二次及以后进入
- **When** 到达同样步骤
- **Then** 提示自动弱化（不再以显著形式打断），且可在 Settings 中重新开启

### AC-14 分享默认隐私
- **Given** 用户从某条日记进入分享
- **When** 页面首次渲染
- **Then** 默认展示卡牌、正逆位、牌阵、核心结论；默认隐藏原始问题、私人笔记、心情、后续记录
- **And** 用户可手动勾选显示原问题；不接入任何真实社交网络 SDK

### AC-15 移动端可用
- **Given** 375×667 及以上的移动视口
- **When** 走完 §28 的完整交付流程
- **Then** 洗牌、切牌、摊牌滑动、拖拽摆牌、翻牌手势均可用手指完成，无横向溢出，无必须依赖鼠标 hover 才能触发的交互

## 6. Product Guardrails 产品红线

> 出现以下任意一项即**打回重做**，无需讨论。Interaction / Frontend / QA Agent 直接对照本表。

**G-01** 点击卡牌后才调用 `random()` / `Math.random()` / `randomCard()` 决定牌面。
**G-02** Hidden Deck State 在 Session 开始时未生成，或生成后被中途整体重新随机。
**G-03** 洗牌是一个按钮（含"一键洗牌""帮我洗""跳过洗牌"）。
**G-04** 系统自动切牌，或提供随机切点、默认切点。
**G-05** 摊牌时并非全部背面朝上，或未翻开的牌以任何方式泄露牌名/正逆位。
**G-06** 牌被自动飞入牌位、自动排布、或点击即落位（无拖拽）。
**G-07** 存在「全部翻开」「自动翻开」「翻牌倒计时」。
**G-08** 翻牌动画包含爆炸粒子、大量闪光、SSR 抽卡表现、强烈震动。
**G-09** 已翻开的牌仍可被替换或重抽；或提供「再抽一次这张」。
**G-10** 换牌操作弹出 Confirm Dialog 打断流程。
**G-11** AI 在牌翻完后自动弹出解读，或在抽牌前/抽牌中给出任何关于结果的暗示。
**G-12** AI 参与决定抽到哪张牌、推荐"更适合的牌"、或根据问题调整牌序。
**G-13** Follow-up 变成无限制通用 Chatbot，或读取历史日记作为 Context。
**G-14** 出现宿命论/确定性表述，或对医疗/财务/法律/危险行为给出确定性预测。
**G-15** 首页做成 Dashboard（仪表盘）；或进入抽牌流程后仍保留完整普通导航。
**G-16** 引入简报 §26 列表中的任何功能，或新增第 6 个牌阵 / 第 2 套牌组。
**G-17** 使用真实 AI API、云数据库、真实登录、付费入口。
**G-18** 视觉滑向廉价紫色玄学网站、游戏抽卡 UI、Crypto Dashboard、电商、ChatGPT Clone。
**G-19** 绝大部分逻辑塞进 `App.tsx`；未按 `components / features / pages / data / types / hooks / utils / store / styles` 分层；Tarot Table 未独立成 Feature Module。
**G-20** 桌面端交互依赖 hover，导致移动端不可用。
**G-21** 为省事把用户交互熵（entropy）伪造成常量，或 `interactionEntropy` 未真正参与牌序计算。
**G-22** 未完成 Session 恢复后牌序或已翻牌状态发生改变。
**G-23** 日记需要用户手动点"保存"才写入。
**G-24** 分享默认暴露原始问题、笔记、心情或后续记录。
