# Phase E4 — Intro Cover 与字体系统

> 在 Reading Experience V2 之上加一层入口封面，并把排版从两档拆成五档。
> Home 的 Card First Hero、Deck 切换、Reading 流式渲染、Share Card、Journal 一行未动。

---

## 1. 审计：问题不在「标题不好看」，在只有两档

改造前全站只有 `--font-sans` / `--font-serif` / `--font-mono`，
外加一条全局 `h1..h6 { font-family: var(--font-serif) }`。

后果是**同一个 token 要同时服务三种要求完全不同的文字**：

| 用途 | 它要什么 |
|---|---|
| 品牌大标题 | 辨识度。它是这个项目的脸 |
| section 标题 | 稳定。用户扫读时不该被字形干扰 |
| AI 解读主题句 | 读得顺。而且**字符集不可枚举** |

挤在一档里，动哪边都会伤到另一边 —— 这才是「标题看起来像默认网页」的结构原因。

另外全站**零字体下载**（纯系统栈），也没有任何 splash / intro 逻辑。

## 2. 字体选型：先确认约束，再选字

三条硬约束决定了可选空间：

1. **CSP 是 `font-src 'self'`** —— Google Fonts 之类的外链会被直接拦掉。
   那条 CSP 是 E2.1 有意加的，不为字体放宽。**必须自托管。**
2. **中文字体动辄 20–30 MB** —— 项目刚做完 23 倍的图片体积优化，
   为装饰性标题加几 MB 是自相矛盾的。
3. **本机没有楷体** —— 近版 macOS 已把 Kaiti 移出默认安装（实测确认）。
   所以「靠系统栈拿到书写感」这条路走不通，必须自带。

### 选定

| 字体 | 角色 | 体积 | 授权 |
|---|---|---:|---|
| **Cormorant Garamond** | 拉丁展示字 | **36.9 KB** | OFL-1.1 |
| **霞鹜文楷 LXGW WenKai Light** | 中文展示字（子集） | **56.6 KB** | OFL-1.1 |

**Cormorant Garamond 是可变字体** —— 一个文件覆盖 300–700 全部字重，
不必为每档各下一个文件。只取 latin 子集。

**霞鹜文楷 Light** 是楷体系，笔画轻、带书写感，是 OFL 授权里最接近
「翩翩体」气质的一款。原文件 **26.9 MB**，子集化到 **223 字**后剩 **56.6 KB（0.2%）**。

合计 **93.4 KB**。OFL 要求授权全文随字体分发，两份 LICENSE 已入库
（这是许可义务，没有任何构建步骤会提醒 —— 由 `deck:check L-04` 守）。

## 3. 五档字体角色

| 档 | 字体 | 用在哪 |
|---|---|---|
| **A Display** | Cormorant（拉丁）+ 文楷（中文子集） | Cover、首页品牌名与 tagline、牌组名 |
| **B Heading** | 系统 serif 栈 | section 标题、**AI 解读主题句** |
| **C Body** | 系统 sans（未动） | 解读正文、用户问题、日记 |
| **D UI** | 同 Body（未动） | 按钮、输入框、标签 |
| **E Card label** | sans + `tracking-wide-caps`（未动） | 过去 / 现在 / 未来 |

### 艺术字的边界是硬的

中文展示字是**子集**，只有 223 个字。它**只用在文案由我们自己写死的地方**。

拿它渲染 AI 解读或用户输入会怎样：缺字**逐字回退**到系统字体，
一句话里出现两种字形 —— 那比不用艺术字更糟，而且**不会报错**。

所以 B 档（Heading）刻意**不含**子集字体：那里会渲染 AI 生成的主题句。
`deck:check L-06` 断言 `ReadingBody` 里不出现 `font-display`。

中英分工靠 `unicode-range`：Cormorant 只声明拉丁范围，中文自动落到文楷。

## 4. Intro Cover

### 为什么不做成路由

做成 `/cover` 有两个真问题：刷新会停在封面而不是用户原本的位置；
别人发来的深链（`/journal/xxx`）会被强行拐去封面。

现在它只是 `/` 这条路由内部的一个前置状态 —— **深链一律直达**，
只有真正「打开这个网站」的人才会看到它。

### 显示策略

`COVER_MODE` 一个常量控制，默认 `session`：

| 值 | 行为 |
|---|---|
| `session`（默认） | 每次新访问显示一次；站内跳转与刷新不再打扰 |
| `always` | 每次进首页都显示 |
| `once` | 本机只显示一次 |
| `off` | 关闭 |

选 `session` 的理由：封面是「进门」这个动作，一次访问进一次门是对的；
站内点来点去时反复关门开门，就变成了阻碍。

存储不可用（无痕、禁 Cookie）时**一律放行** —— 封面不该挡住任何人。

### 两个在测试中撞到的真缺陷

**① 入场淡入依赖 `requestAnimationFrame`。**
后台标签页里 rAF 会被浏览器挂起，回调可能一直不执行 ——
封面停在 `opacity: 0`，用户切回来看到的是**一片空白**。
改成纯 CSS 动画，不依赖 JS 调度。

**② 离场只有一个 `setTimeout(220)`。**
定时器在后台标签页会被节流到 1 秒以上。用户点完 Enter 立刻切走、
过一会儿回来，这一层还挂着 —— 它 `opacity` 已经是 0 看不见，
但 `z-50` 的全屏容器**仍然吃掉所有点击**，首页整个点不动，且没有任何报错。

改成三重保障：`transitionend` 为主 + 定时器兜底 + 离场期间 `pointer-events-none`。

## 5. 可访问性：用 canvas 量对比度，不手写解析器

第一次用正则解析 `getComputedStyle().color` 算出 **1.03:1** —— 明显是假值：
颜色是 `oklch()`，手写正则解析不了。改用 canvas 做真实 oklch→sRGB 转换：

| | 对比度 |
|---|---|
| 标题 / 按钮文字 | 16.40:1 ✓ AAA |
| 引导语 18px | 5.55:1 ✓ AA |
| 底部小字 13px | **3.11:1 ⚠ → 已修为 5.55:1** |

最后一条是本轮引入的（用了 `text-faint`）。封面上一共四行字，
没有一行可以是「看不清也无所谓」的。

Enter 按钮 `autoFocus`、可 Tab、有 `focus-visible` 描边、`prefers-reduced-motion` 下动画归零。

## 6. 移动端与性能

375 / 390 / 430 实测：无横向溢出 · 标题单行 · 引导语单行 · 按钮 55px（>44px）。
标题用 `clamp(2.75rem, 11vw, 5.5rem)`，375 上 44px、桌面 88px，连续无断点跳变。

字体 `preload` + `crossorigin` + `font-display: swap`。
封面上没有任何牌面图，这两个请求不和图片抢带宽。
零 canvas / WebGL / 重型动画。

### Streamlit 形态

`@font-face` 写的是绝对路径 `/fonts/...`，而组件挂在
`/component/streamlit_app.arcana/` 下 —— 这正是项目文档警告过的那类 404。
实测 Vite 的 `base: './'` 已正确改写（CSS 变 `../fonts/`、preload 变 `./fonts/`），
浏览器里两个字体均 **200 且真加载**。
