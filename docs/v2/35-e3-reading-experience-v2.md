# Phase E3 — Reading Experience V2

> 参考 Lenormand/Stargazer 一类 oracle 站点的**设计原则**（Card First、留白、
> Result First），不复制其视觉。多 Deck、牌阵、牌义、AI 解读、spreadLayout
> 五个稳定模块一行未动。

---

## 1. 审计先于修改 —— 三个与预期相反的结论

改造前先读了一遍全部相关页面与组件。三条结论推翻了原本的假设，也决定了本轮**不做什么**：

| 原假设 | 实际情况 |
|---|---|
| Atmosphere 抢占了卡牌的视觉注意力 | **相反 —— 它太弱**。十套各自本来就有专属 SVG（光柱 / 退潮线 / 拱门藤蔓 / 月晕 / 帷幕），但 `fillOpacity` 只有 **0.028–0.07**，人眼基本看不见 |
| 装饰是性能包袱 | blur 8 处（全在 atmosphere）、backdrop-filter 2 处、持续动画 2 个（均有 `motion-reduce` 保护）、粒子是模块加载时算一次的**静态种子点**。这一层已经很克制 |
| 卡牌缺实体感 | `CardFrame` 已单点掌管单层双段 shadow、边缘内光、牌组内衬线、暗角，且**刻意不加 glow**。基础扎实 |

所以本轮**没有**重建氛围层、**没有**重写 CardFrame、**没有**碰 spreadLayout 引擎。

### 真正的缺口

- **Home 零卡牌** —— 纯文字 + 两个文字按钮
- **Reading 页不显示用户问题** —— 解读是对那句话的回应，标题却不是那句话
- **Loading 与结果是两个互斥分支** —— `done` 时整块替换
- **牌之后有 9.6 秒死窗口**（下一节）

## 2. 死窗口：传输是流式的，体验却是「等完整结果」

D5 修好了牌**之前**那一段（`extractPartialCards`）。E3 实测发现牌**之后**还有一段更长的空白：

```
最后一张牌解释上屏   10.4s
解读被标记完成       19.3s
中间 9.6 秒（占总时长 48%）屏幕上没有任何新内容
```

那 9.6 秒模型并没有闲着，它在写 `relationships` / `narrative` /
`answerToQuestion` / `reflectionQuestions`。这些字段**本来就在流里**，
只是全被折叠区扣着等 `done` 才一次性出现。

### 一个考虑过并否决的方案

更直接的办法是把 `answerToQuestion` 在输出契约里提到最前面 —— 用户最想要的那段就能在 6 秒而不是 17 秒出现。**不这么做**：

standard 模式 `thinking: { type: 'disabled' }`，JSON 正文本身就是模型的推理过程。
让它在逐张分析之前先写结论，等于要求它凭尚未展开的牌面下判断。
那是拿解读质量换首屏速度。

**字段顺序不动，改的是前端什么时候把它们放出来。**

### 做法

`streamClient.ts` 新增两个提取器，与既有的 `extractPartialCards` 同一条原则 ——
**只取已闭合的字符串，不显示半句**：

- `extractPartialRelationships()` —— 判据是 `"interpretation": "…"` 后面跟 `}`。
  `cards[].interpretation` 后面跟的是逗号，所以不会把三张牌的解释误当成三条牌间关系
  （`PERF-08j` 锁住这一条）
- `extractPartialStringList()` —— 字符串数组，逐元素放出

`ReadingBody.tsx` 让**流式与完成态共用同一套渲染**。这是「`done` 时整块替换」的根因：
形状不同就必然要两套分支。段落顺序刻意与模型输出顺序一致，
所以新内容永远追加在底部，不会插到用户正在读的段落上方。

### 实测对比（同一条生产链路）

| | 改造前 | 改造后 |
|---|---:|---:|
| 上屏事件数 | 8 | **17** |
| 最长无新内容间隔 | **9.6s（48%）** | **2.57s（16%）** |
| 首字 | 1.9s | 1.56s |

## 3. Card First 首页

左右分栏：左边三张**当前牌组的真实牌面**错落叠压，右边徽记 + 品牌 + tagline + 单一 primary CTA。换牌组时牌与徽记一起变。

- 三张而不是五张：错落叠压才读作「一副牌」，三张是能同时看清每张主体的上限
- `rotate` 只有 −4° / 0° / 3.5°：大角度会立刻变成游戏抽卡界面
- 全部 `variant="thumb"` —— **13KB/张 vs 295KB/张，23 倍差距**。首屏三张牌差的是 39KB 还是 885KB

## 4. Reading 页信息层级

```
你的问题
「我应该接受这个实习机会吗」        ← serif 大标题，页面的锚点
过去 / 现在 / 未来
[ 牌 ]      [ 牌 ]      [ 牌 ]     ← 90–160px，不再是缩略条
─────
解读正文（渐进）
```

顺带修掉一个**静默 bug**：原来写的是 `<CardFrame size="sm" className="w-10">`，
而 `CardFrame` 的宽度走 inline style ——「className 上的宽度被静默忽略」
正是它自己文档里警告过的陷阱。牌从来就不是 40px。现在走 `width` 这个唯一出口。

### 尺寸是算出来的，不是试出来的

第一版用 26vw / 5vw，桌面上很好，而 375px 上五张牌算出 **380px** —— 比容器宽 35px。
那种 bug 在 1440 的屏幕上永远不会被看到。

现在：可用内容宽 = `min(92vw, 40rem) − 32px`。

| 视口 | 3 张 | 5 张 | 桌面 3 张间距 |
|---|---|---|---|
| 375 | 300 / 313 ✓ | 293 / 313 ✓ | |
| 390 | 312 / 327 ✓ | 304 / 327 ✓ | |
| 430 | 344 / 364 ✓ | 335 / 364 ✓ | |
| 1440 | 550 / 608 ✓ | 597 / 608 ✓ | **58px**（要求 48–72） |

`layout:check` 把这套算术固定下来（14 条新断言），浏览器 iframe 实测值与脚本计算值**完全一致**。

## 5. Deck Signature

不重建氛围层，补一个**可读**的锚点：`DeckSigil`。五种构图沿用牌组已有的
`cardBack.composition` 分类（lunar / orbit / botanic / constellation / veil），
右上角，opacity **0.11** —— 扫一眼能注意到，盯着看才看清；再高会在深色底上形成抢眼亮斑。

为什么不靠色相：chroma ≤ 0.05 时两个色相人眼几乎分不出。
为什么不靠粒子和 blur：项目已有性能预算。
一个形状明确、位置固定、完全静止的图形，是这三者里唯一既便宜又一眼可分的。

克制边界由 `deck:check` K 组守：**0 blur · 0 动画 · 0 canvas/WebGL**，且五套两两不同。

## 6. Share Card

固定 **1080×1350**，内部全部用 `cqw` 容器查询单位 —— 同一份 DOM 在预览里 320px、
导出时 1080px，版式完全一致。用户问题**默认不出现**（AC-14），由用户自己勾。

### 为什么没有「保存图片」按钮

实测 R2 的 `.r2.dev` **不返回 `Access-Control-Allow-Origin`**：

```
curl -I -H "Origin: https://arcana-e190.onrender.com" <r2>/…/major-00.webp
HTTP/1.1 200 OK
Content-Type: image/webp
（无 access-control-allow-origin）
```

canvas 一旦画入跨源图片就会被污染，`toBlob()` 直接抛 SecurityError。
本地资产模式（同源）反而能成 —— 也就是说那会是一个**开发能用、上线就坏**的按钮。
前置条件是给 R2 桶配 CORS，属基础设施改动，不在本轮范围。

## 7. 改了两条既有断言，都没有删

| 断言 | 为什么改 |
|---|---|
| `REL-07` 首页不挂载任何牌面组件 | 与 Card First 直接冲突。但它守的首屏预算没过时 —— 换成**更严的三条**：≤3 张 + 必须 thumb + 不预热。原规则禁止「首页有牌」，新规则允许「有牌」但禁止「有重牌」，而且现在可量化 |
| `PERF-08f` 标准模式不显示「1–2 分钟」 | 判据是一条匹配旧源码字面量的正则，锁的是「那一行长什么样」而非行为。文案挪进状态行后它就红了，而行为一个字没变。改成守不变量：「1–2 分钟」只允许出现在 deep 分支 |

写新断言时犯了同一类错：`K-03` / `K-05` 第一次红，是因为正则匹配到了
`DeckSigil` **文档注释里**「无 blur、无 canvas」那句说明文字。
断言扫源码时不排除注释，守的就是「有没有提到这个词」而不是「有没有用这个东西」。已改成先剥注释再判。
