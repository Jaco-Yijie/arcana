# Deep Reading 稳定性（V2.4 P0）

## 目标与结论

**目标**：Deep 模式连续 20 次真实调用，成功 ≥ 19 次。

「成功」的判定很严格 —— 必须走完整条链路：
流式取回 → JSON 解析（必要时修复）→ **逐张比对牌面** → 语气校验。
任何一步不过都算失败。**牌面对不上一律算失败，不管解读写得多好。**

| 轮次 | 结果 | 失败原因 | 说明 |
|---|---|---|---|
| 修复前基线（V2.3 A/B 采样） | **8/10** | 空响应 ×1、JSON 语法错 ×1 | 问题的起点 |
| 第 1 轮（JSON 修复上线后） | **19/20** | `schema-invalid` ×1 | 暴露出两个**校验器误杀** |
| 第 2 轮（校验边界修正后） | **19/20** | `tone-blocked` ×1 | 暴露出一个**语气误杀** |
| 第 3 轮（让步句识别上线后） | **20/20** | 无 | 一次过 20，零重试 |

三轮共 60 次真实调用，**牌面一致性违规 0 次**。

第 3 轮 20 次全部**第一次尝试就成功**，一次重试都没用到，也没有一次动用 JSON 修复 ——
说明前两轮修掉的是**校验器的误杀**，而不是靠重试去掩盖模型的不稳定。
延迟：中位 99.1s，P90 115.3s，最长 117.1s。

复现：`npm run deep:stability`（打真实接口，不接受 Mock）

## 三类失效，三种处理

### 1. JSON 语法错误 → 定向修复

真实样本（`ab-out/07-五张-关系类__v2-deep.raw.json`，4942 字符）：

```json
"answerToQuestion": "……现在更需要的是：一次基于真实的对话。"
  "reflectionQuestions": [
```

尾部 `}` 完好，全文完整 —— **只是漏了一个逗号**。
为这个丢掉一整份 4000 字解读、让用户重等 90 秒，不划算。

`server/validation/jsonRepair.ts` 是一个**知道自己在不在字符串里**的状态机，
只修三类结构问题：漏逗号、多逗号、截断（回退到最后一个完整值）。

**为什么不用宽松解析器或正则**：解读正文里大量出现 `"`、`{`、`,`、中文引号。
正则分不清「结构里的逗号」和「正文里的逗号」，改错了就是**篡改用户看到的内容** ——
那比解析失败严重得多。

无损性验证：对 28 份本来就合法的真实样本，修复器输出**逐字节一致，零改动**。

### 2. 空响应 → 重试

模型只产出 reasoning、`content` 为空（DeepSeek 官方文档承认的已知情况）。
这类没有别的办法，只能重试。

### 3. 校验器误杀 → 收紧红线的边界

这是 20 次真实测试最有价值的产出：**两次失败都不是模型改牌，却都被当成改牌处理了。**

| 模型实际写的 | 旧判定 | 问题 |
|---|---|---|
| `"orientation": "up right"` | 「模型改变了正逆位」→ 整份作废 | 意思毫无歧义，只是多了个空格 |
| 某张牌漏了 `connectionToQuestion` | 「不是字符串」→ 整份作废 | 牌面完全正确，只是少了一段文字 |

修正后：

- **正逆位**：先归一化写法（空格 / 连字符 / 大小写 / 中文「正位」「逆位」），
  只有归一化后**明确等于相反方向**才作废。
  红线没有松动 —— 模型真把 upright 写成 reversed，照样整份作废。
- **`connectionToQuestion` 缺失**：标 `repaired`、留空，前端跳过这一段。
  **绝不编造内容填进去。** `interpretation` 仍然必填（缺了这张牌就真的没内容了）。

## 重试策略：最多一次，且什么都不许换

实现在 `server/reading/generateReading.ts`，**与 20 次测试脚本共用同一个函数** ——
脚本里再抄一份重试逻辑的话，测的就不是线上真正跑的东西了。

```
generateStructuredReading(context, hooks)
  attempt() ─┬─ 成功 → 返回
             └─ 失败 且 isTransient → onRestart() → attempt() ← 就这一次，没有第三次
                                                      └─ 再失败 → 如实报错
```

**重试期间原样复用同一个 `context` 对象**：问题、牌阵、每张牌的 cardId、正逆位、牌位、
`readingMode` 全部不变。这条路径上：

- 没有任何随机数 —— **不可能重新抽牌**
- 没有任何分支能把 deep 换成 standard
- 没有任何分支能把 deep 换成 mock

值得重试的只有模型侧偶发问题（`empty-response` / `invalid-json` / `timeout` /
`upstream-error` / `network-error` / `SchemaError`）。配置错误、鉴权失败重试也没用，直接报错。

语气拦截也走这同一次重试 —— 它和「JSON 坏了」一样是偶发的模型侧问题，
没理由直接把失败甩给用户。

### 两次都失败之后

前端**保留全部牌面状态**，显示：

> 这次深度解读没有完整生成，你抽出的牌已经保留。

并给两个选项：**再次尝试深度解读** / **改用标准解读**。

换成标准解读是**用户主动**做的选择，不是我们背着他偷偷降级。牌一张都不动。

## Validator 误报收敛

原则没变：**Validator 只拦截真正明显的问题，不做语言风格控制器。**
禁止靠堆关键词黑名单解决。

V2.4 新增的唯一一条豁免是**让步转折结构**。真实样本：

> 「虽然加速**不可避免**，但你可以选择在开始加速前，先把方向对准。」

整句在强调**用户仍然有选择权** —— 恰恰是我们要求模型写的反宿命表达，
却因为里面有「不可避免」四个字被判成宿命论，把 5000 字解读整份作废。

**为什么不是加白名单短语**：这不是词的问题，是句法结构的问题。
让步从句里的「不可避免」描述的是**前提**，真正的主句在「但」后面。
识别结构比枚举短语稳得多，也不会越滚越长。

必须同时满足两个条件才豁免：

1. 命中词**前** 14 字内有让步标记（虽然 / 尽管 / 即便 / 即使 / 纵然 / 就算 / 哪怕 / 固然）
2. 命中词**后** 20 字内有转折标记（但 / 不过 / 然而 / 仍然 / 依然 / 还是 / 取决于 / 你可以）

且只对 `determinism` 类规则开放 —— 玄学词包在让步句里仍然是空洞玄学。

反向验证（有断言）：

| 文本 | 结果 |
|---|---|
| 虽然加速不可避免，但你可以选择在开始加速前，先把方向对准。 | 放行 ✓ |
| 尽管这次调整无法避免，不过你仍然决定要往哪边走。 | 放行 ✓ |
| 即使有些事已成定局，你还是可以决定接下来怎么做。 | 放行 ✓ |
| 这个局面已成定局，无法改变。 | **拦截** ✓ |
| 虽然你很累，但这件事已成定局，无法改变。 | **拦截** ✓（没把选择权还回来） |
| 虽然天意如此，但你可以选择怎么走。 | **拦截** ✓（玄学类不豁免） |

## 延迟（不是本轮目标，仅作记录）

三轮实测：中位 70–99 秒，P90 110–115 秒，最长 143 秒。

这与 `14-perf-investigation.md` 的结论一致：**耗时由模型生成主导**，
输入是 99.2% 缓存命中、TTFB 0.3 秒。所以缩短 Prompt 对速度是**无效杠杆**。

真正改善体验的是流式渐进渲染（首字从 45.5s 降到 1.1s），
以及在选择模式时就如实告诉用户「通常需要等待更长时间」。
