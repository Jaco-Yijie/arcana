# 牌组插画资产

这个目录是**五套 artwork 牌组唯一的牌面来源**。代码不会从别处找图，也不会在缺图时
用程序化 SVG 或别的牌组的图顶上 —— 缺什么，界面上就如实显示什么。

## 目录

```
public/assets/decks/<deckId>/
  deck/
    cover.webp            1200 × 2000   牌组封面（不是任何一张牌）
    back.webp             1080 × 1800   卡背，78 张共用一张
  cards/
    major-00.webp … pentacles-14.webp   1080 × 1800，扁平 78 个
  thumbs/
    major-00.webp …                     240 × 400，脚本生成，美术不用提供
```

`<deckId>` 只有五个：`ethereal` `elysian` `opaline` `wonderland` `classic`。

### 为什么封面和卡背在 `deck/` 里

它们不属于任何一张牌。分开成物理目录之后，「封面绝不能是 78 张里的某一张」
这条约束在文件系统层面也成立 —— 不可能"顺手"把一张牌放成封面。

### 为什么不分 `major/` `minor/`

那条边界是牌义层的语义（`TarotCard.arcana`）。路径一旦依赖它，
拼 URL 的代码就必须回答「这张是大阿卡纳吗」，只有两条路：import 牌义层
（把整个架构最想避免的耦合拉回来），或者解析 `cardId.startsWith('major-')`
（把分类规则复制一份，两份迟早不同步）。而且它制造双真相源：
`major-00.webp` 物理上可以被放进 `minor/`，错误只表现为 404。

78 张扁平放一个目录，`ls` 的字典序天然分成 5 组，够用了。

## 命名硬规则

1. **文件名必须等于 cardId**，逐字符一致。不用牌名、不用中文、不用自定序号 ——
   牌名可能改文案，cardId 永不改。
2. 小阿卡纳**两位补零**：`wands-01`，不是 `wands-1`。11=侍者 12=骑士 13=王后 14=国王。
3. **不要提供 `-reversed` 版本。** 逆位 = 同一张图 `rotate(180deg)`。
   允许独立逆位资产必然产生「12 张有专门逆位图、66 张没有」的半状态。
4. **不要在图里烘焙任何文字或数字。** 牌名与编号由代码在图上绘制。
   图里出现任何字，180° 旋转时就会倒过来。
5. 因为第 3 条，**构图必须可 180° 阅读**：不要强重力构图，四角装饰尽量对称，
   主体尽量居中。交付前请把每张图旋转 180° 自己看一遍。
6. 边缘 6% 安全区（卡片有圆角与内描边）；底部 22% 会被牌名渐变压住，
   不要在那里放主体。

## 规格

| 项 | 值 |
|---|---|
| 格式 | WebP，质量 78，无 alpha，sRGB 嵌入 profile |
| 牌面 | **1080 × 1800**（严格 1:1.667），≤ 220KB |
| 卡背 | 1080 × 1800，≤ 180KB |
| 封面 | 1200 × 2000，≤ 260KB |

**不需要 @2x / @3x。** 全站最大展示是 176 CSS px，@3x 设备也只要 528 物理像素，
1080 已有 2 倍余量。改用 thumb + full 两档：780 个文件约 93MB，
而三档是 1170 个文件约 170MB。

## 修订号（rev）—— 返修流程

**目录里没有 rev，磁盘布局就是上面那样。** rev 只作为查询参数出现在运行期 URL 上：

```
/assets/decks/ethereal/cards/major-00.webp?r=3
```

静态资产按内容不变的假设发一年 `immutable` 缓存，而牌面文件名按设计恒定。
没有 rev 的话，返修一版画，已访问过的用户一年都看不到，且没有任何逃生口。

（第一版曾经把 rev 做成路径段 `…/<deckId>/r1/cards/…`，那是个「交付即坏」的陷阱：
磁盘、本文件、`deck:check` 三处都没有 `r1` 这一层，素材放进去后
浏览器会拿到 SPA 兜底的 index.html，每张牌都显示「加载失败」，而断言全绿。
现在 `deck:check` 有一条「运行期 URL 与磁盘路径指向同一位置」的对照断言，
任何人再把两者改岔都会立刻变红。）

返修流程：换掉文件 → 在 `src/decks/artwork/manifests.ts` 里把该牌组的 `rev` 加一
（或只给那一张牌加 `rev` 覆盖，避免让用户重下 78 张）→ 旧 URL 自然失效。
回滚就是把 rev 改回去。

## 交付之后

放进目录**还不够**，必须在 `src/decks/artwork/manifests.ts` 里登记
（含像素宽高与是否有缩略图）。未登记的资产不会被使用。

跑 `npm run deck:check` 验证。它会双向检查：登记了但文件不存在、
文件存在但没登记，两个方向都报。`npm run build` 已经包含这一步，过不了就构建失败。

## 五套之间的关系

**同一个模特，拍五组照片。** 五套画的是同一批 78 张牌，变量**只有画风**。

- 不要让某一套的某几张"画得特别用力"。用户会把画面用心程度读成"这张牌更灵"。
- **五套必须同步交付。** 不接受"先把一套画完" —— 那会制造一段
  "某副牌明显更高级"的时期。代码层面也挡着：coverage 只允许 0 / 22 / 78 三档。

## Phase 1 交付清单（每套 7 个 × 5 套 = 35 个）

| 文件 | 说明 |
|---|---|
| `deck/cover.webp` | 封面。**不能是 78 张里的任何一张牌** |
| `deck/back.webp` | 卡背 |
| `cards/major-00.webp` | The Fool 愚者 —— 人物 + 空间 |
| `cards/major-01.webp` | The Magician 魔术师 —— 器物 + 光源 |
| `cards/major-02.webp` | The High Priestess 女祭司 —— 对称构图 + 织物材质 |
| `cards/major-13.webp` | Death 死神 —— 最难画不落俗套的一张 |
| `cards/major-17.webp` | The Star 星星 —— 大面积留白 + 水面反光 |

这 5 张是**横向对比对照组**：五套必须画同样这 5 张，
才能验证同一个 cardId 在五副牌下真的有不同的主体插画、构图、边框、配色与装饰。

各套的视觉方向与逐张 brief 见 `docs/v2/19-deck-visual-identity.md`。

## 切 CDN

Phase 3 的 390 张不该进 Git。切换只需一个环境变量，代码不用改：

```
VITE_DECK_ASSET_BASE_URL=https://cdn.example.com/arcana/decks
```

所有资产 URL 只从 `src/decks/artwork/paths.ts` 产出，就是为了这一刻。
注意它是**构建期**内联的，Docker / deploy 脚本需要透传该变量。
